## 四、需求 4：怪物密度（答案就在配置里）

### 结论：改 `config.yaml` **两行**，不用改库、不用重编译，**重启服务端生效**

```yaml
# config.yaml:263
- USE_ENABLE_FULL_RESPAWN: false   # 我现在看到的默认值
+ USE_ENABLE_FULL_RESPAWN: true    # ★ 关键：每次补怪都把 spawn 点填满

# config.yaml:178（可选，想刷得更快就调）
- RESPAWN_INTERVAL: 10000          # 10 秒补一次
+ RESPAWN_INTERVAL: 3000           # 3 秒补一次（30 秒内可把图填满）
```

### 为什么是这两行（代码依据）

`Server.java:877` 注册了 `RespawnTask`，周期 = `RESPAWN_INTERVAL`；任务调 `MapleMap.respawn()`（`:3707`），里面：

```java
int numShouldSpawn = getNumShouldSpawn(numPlayers);   // :3724

private static double getCurrentSpawnRate(int numPlayers) {   // :3685
    return 0.70 + (0.05 * Math.min(6, numPlayers));           // 单人 = 0.75
}

private int getNumShouldSpawn(int numPlayers) {               // :3689
    if (YamlConfig.config.server.USE_ENABLE_FULL_RESPAWN) {
        return (monsterSpawn.size() - spawnedMonstersOnMap.get());   // ← 补满
    }
    int maxNumShouldSpawn = (int) Math.ceil(getCurrentSpawnRate(numPlayers) * monsterSpawn.size());
    return maxNumShouldSpawn - spawnedMonstersOnMap.get();        // ← 只补到 75%
}
```

⇒ **现在（单人）每张图最多只维持 75% 的怪**，剩下 25% 永远空着。改成 `true` 立刻变成 100%。
⇒ 另注意 `respawn()` 开头有 `if (numPlayers == 0) return;`（`:3717`）—— 单人玩没问题，但**在图里没人时不补怪**，属正常。

### ⚠️ 有一个上限绕不过去

**每张图的 spawn 点数是地图自带、写死在 wz 里的**（`MapleMap.monsterSpawn` ← `Map.wz` 的 `life` 节点）。上面两行只能让每张图**填满到它的原始上限**，**不能凭空变多**。

想突破原始上限，只有三条路：

| 办法 | 效果 | 成本 |
|---|---|---|
| **`USE_ENABLE_FULL_RESPAWN: true`**（推荐） | 由 75% → 100%，**立刻生效** | 改 1 行配置 |
| 用主菜单 `#L19# 生成怪物` | 想要多少刷多少 | 每次手动，换图/重登即失效 |
| 改 `wz\Map.wz` 的 `life` 节点 | 永久提高某图上限 | 要改 wz（xml 可改），工作量大、影响全局，**不建议** |

**"改库里某个字段"这条路不存在** —— 地图怪物是 wz 静态数据，MySQL 里没有相关表。这是实话。

## 9.2 你问的「一键清零背包」：有，而且能按类别

入口：**主菜单 `#L27#` 背包管理（一键按栏位清理）**

```
[0] 清理装备栏（现有 N 件）    [3] 清理其他栏（现有 N 件）
[1] 清理消耗栏（现有 N 件）    [4] 清理装饰栏（现有 N 件）
[2] 清理设置栏（现有 N 件）    [5] 清理全部（不含装饰栏）
                              [6] 返回主菜单
```

**三条安全设计（这是本轮最花心思的地方）**

| # | 设计 | 为什么 |
|---|---|---|
| 1 | **必须二次确认** | 点栏位后先出「将清掉 N 件物品 / 此操作不可撤销」，再点「确认清理 N 件」才真删；点「取消，返回」什么都不做 |
| 2 | **删的是槽位，不是物品 ID** | 用 `MapleInventoryManipulator.removeFromSlot(client, type, slot, qty, fromDrop)`（`:392`）。按槽位删 ⇒ 不会误伤"身上穿着的同 ID 装备" |
| 3 | **"全部"永远不含装饰栏** | `SAFE_BAG_TYPES = [5]`（装饰栏）。装饰栏装着点装/披风之类，误清损失大，所以"全部"明确跳过它 |

**为什么身上装备一定安全**：服务端的 `EQUIP`（背包）与 `EQUIPPED`（身上）是**两套独立数组**，
本功能只遍历 `MapleInventoryType` 的 1~5（装备/消耗/设置/其他/装饰），
**根本不碰 `EQUIPPED(-1)`**；冒烟测试直接断言了 `-1:` 与 `5:` 不会出现在删除调用里。

**另一个坑**：遍历背包时**先把 `list()` 快照成数组**再逐个删，
不能边遍历边删（`Collections.unmodifiableCollection` 会抛 `ConcurrentModificationException`）。

**空栏位**：本来就空的话，提示"这一栏本来就是空的，没什么可清"，**不给确认按钮**（只有一个「返回」）。

## 9.4 ★ 本轮踩到的真坑：模板占位符被多套了一层 `[`

**症状**：语法没错、GB2312 也过、生成器校验也过，但**点菜单才发现坏了**——
档位菜单只剩「返回」一项，档名被拼成了整串数据。

**原因**：模板写的是

```js
var BOSS_TIERS = [
/*@BOSS_TIERS@*/
];
```

而占位符替换进去的内容**本身就是完整的数组字面量**（自带最外层 `[]`），于是变成 `[[[...]]]`，
`BOSS_TIERS.length === 1`。

**修法**：模板改成 `var BOSS_TIERS = /*@BOSS_TIERS@*/;`（注释里写明"别再套一层"）。

**加守卫**：`gen_gm_menu.py` 现在会在**装配前**用 `ast.literal_eval` 校验数据块顶层正好 3 档、
每档 12 只；装配后**再解析一次生成结果**里的 `BOSS_TIERS` 字面量。这类"语法合法但结构错"的问题
从此在生成阶段就会被拦下，不会流到游戏里。

> 教训值得记：**能用 `ast.literal_eval` 校验的注入数据，就别只靠正则数条目**。
> 正则数"有 36 个 `[数字, "名字", 等级, HP]`"是对的，但它对**外层嵌套**完全不敏感。

`dump_gm_menu.js`（预览脚本）里有两处 `action(1, 0, 12)` 用来打开「按名字搜索」。
