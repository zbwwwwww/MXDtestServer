## 一、登录 / 账号（坑 A）

1. 客户端报「用户不存在」**不是错误**：自动注册机制要求**连点 3 次**登录（`LoginPasswordHandler.java:97-100`）
2. 密码存的是 bcrypt（`$2y$12$`）—— **别手插明文账号**
3. 改 `characters` 表（含 `gm` 字段）**必须先退出游戏**：角色数据内存权威，autosave 每小时覆盖写回 DB
4. `isGM()` 判定是 `gmLevel > 1`；`USE_ENFORCE_ADMIN_ACCOUNT` 必须为 true

## 二、技能 / wz / 数据库（坑 C）

| # | 坑 | 说明与对策 |
|---|---|---|
| 1 | **HikariCP 从未生效** | `new DatabaseConnection()` **全项目零调用** ⇒ 即使 `DB_CONNECTION_POOL: true`，`ds` 恒为 null ⇒ 每条 SQL 新建一条 TCP 连接（~5 条/秒）。**修法：启动时调一次**（待做，记作"修复 E"） |
| 2 | **wz 解析别手写层级扫描器** | `Skill.wz/000.img.xml` 真有短 ID 技能（`8/12/100/1000~1031/9000~9002`），`getSkill(12)` **非 null** 是正常命中、无害。手写扫描器会误判 → **直接跑真代码验证** |
| 3 | **String.wz 只有 10 个 img** | Cash / Consume / Eqp / Etc / Ins / Map / Mob / Npc / Pet / UIWindow —— **没有 Skill.img**。任何依赖 `String.wz/Skill.img` 的代码都会 NPE |
| 4 | **改方法前先查调用方** | `GameConstants.getJobName(int)` 返回**英文名**，被 `MapleCharacter.java:1312` 的英文转职公告使用，**不能改**。中文名走新增的 `getJobNameCn(int)` |
| 5 | **两处会让 NPC 永久点不动** | ① `maxMastery()` 读不存在的 `String.wz/Skill.img` 且写在 `try` 外 → NPE 逃出 → `dispose()` 不执行；② `NPCScriptManager.action()` 原来只 catch `ScriptException\|NoSuchMethodException`，脚本抛 `RuntimeException` 同样搞死 NPC。**都已修** |
| 6 | **地图不存在时 NPE** | `loadMapFromWz` 会 NPE；已加 `MapleMapFactory.mapExists(int)` |
| 7 | **SQL 导入顺序** | `db_database`→`db_drops`→`db_shopupdate`→`db_buchong`→`db_huodong`；`temp_data` 跑完自动 DROP；**不能单独重跑 db_drops** |
| 8 | **`dumpSqlTask()` 平台问题** | 原写死 Linux 路径（Windows 报 `CreateProcess error=2`），已改 ProcessBuilder；备份目录 `saves` |
| 9 | **封包中文硬编码 GB2312** | `GenericLittleEndianWriter.java:35`，与 `-Dfile.encoding` 无关 ⇒ **脚本字符串里的中文必须 GB2312 可编码**，别用 emoji |
| 10 | **`config.yaml` 必须保留双引号** | YAML 值里的密码含 `#` / `?`，去掉引号会被当注释/特殊符 |
| 11 | **三种 chance 语义不同** | `drop_data` 是**百万分比**（1000000=100%，越大越易掉）；`drop_data_global` 同但不乘倍率；`reactordrops` 是**分母**（1=100%，越小越易掉） |
| 12 | **掉落改大不会崩** | `MapleMap.java:656-658` 有 `Math.min(..., Integer.MAX_VALUE)` 夹住，且按怪惰性读，与登录零交集 |
| 13 | **封包调试开关** | `USE_DEBUG_SHOW_RCVD_PACKET: true` 打印 `Received packet id <十进制>`；`GENERAL_CHAT=49`、`ADMIN_COMMAND=128` |
| 14 | **新增同名方法会报「已定义」** | `changeJobById` 本来就有（`:348`，void）；改返回类型对 JS 无影响 |

## 三、数据分布与缓存（改完要不要重启）

**DB 里没有「物品表 / 怪物表 / 经验倍率表」** —— 静态配置全在 wz XML：

| 数据 | 位置 |
|---|---|
| 怪物 HP/EXP/等级/攻防 | `wz/Mob.wz/<7位补零ID>.img.xml` → `info`（蜗牛 `0100100.img.xml`：exp=3、maxHP=8、lv=1） |
| 怪物 / 物品 / 地图名 | `wz/String.wz/*.img.xml`（共 27238 条中文名） |
| 掉落关系 | DB `drop_data`(22309) / `drop_data_global`(6) / `reactordrops`(1116) |
| 倍率 | `config.yaml` 的 `worlds[].exp_rate/drop_rate`（world0：exp=5、drop=1） |

**wz 解析套路**：只把「纯数字」的 `<imgdir name="...">` 当条目 ID，跳过 Eqp/Accessory 分类层，通吃全部 String.wz。

**重启规则（重要）**
- 改 **DB / `config.yaml` / wz / Java 代码** ⇒ **必须重启服务端**；客户端不用动
- 改 **脚本** ⇒ 只需**完全关闭客户端重开**（脚本按 `MapleClient` 缓存 engine）；服务端不用重启
- 原因：数据**永久缓存且无热重载入口**（`clearDrops()` / `reloadShops()` 存在但零调用方）
- ⚠️ `characters` 表**绝不能在线改**

## 四、构建 / 部署（改完代码必读，不打包=没生效）

**服务端加载的是「编译产物」，不是 src** —— 但**加载哪一份取决于启动方式**（09-21 实测确认）：

| 启动方式 | 实际加载的 class | 改完代码要更新哪里 |
|---|---|---|
| **IDEA Run/Debug**（常用，`-agentlib:jdwp`） | `D:\MXDtestServer\out\production\SERVER083\*.class` | `py D:\tmp\deploy_classes.py <文件...>` |
| `start-server.bat` → `java -jar …HeavenMS-zhoubw_083.jar` | jar 内的 class | `py D:\tmp\patch_jar.py <文件...>` |

**最稳：两个都跑**（`deploy_classes.py` + `patch_jar.py`）。查当前进程加载哪份：

```bash
# 看 -classpath 里有没有 out\production\SERVER083；有 = IDEA 启动
# 或比对：进程 CreationDate vs 文件 mtime —— 进程启动早于改动 ⇒ 一定没生效
```

⚠️ **`mxd_build.py check` 只写 `D:\tmp\hotkey-test`、`full` 只 `jar uf` ⇒ 都不碰 `out\production`**（IDEA 启动时"改了没生效"就是这个原因，F1/F2 白改过两轮）。
⚠️ `full` 还会因 `rmtree` 935 个文件被沙箱「批量删除保护」拦掉 ⇒ 别用。

（jar 自包含，已内嵌 mina / hikari / mysql / slf4j / yamlbeans 等全部依赖；manifest 只有 `Main-Class: net.server.Server`）

```bash
javac -g -encoding UTF-8 -nowarn -d <临时目录> -cp "D:\MXDtestServer\cores\*" @D:\tmp\mxd-verify3\sources.txt   # 628 源文件 → 934 class，~30s
cd <临时目录> && jar uf "...\HeavenMS-zhoubw_083.jar" .      # uf 只覆盖自己的 class，manifest 保留
```

- **必须带 `-g`**（= IDEA artifact 的调试信息）。不带 `-g` 会让 **895/2027** 个条目全变、jar 小 217KB，你就无法判断真实改动；带 `-g` 后 `diff -rq` 会收敛到真改过的源文件
- `out\production\SERVER083` 是 IDEA 的编译输出，**不是运行态**
- 校验法：`jar xf` 解到两个目录 → `diff -rq old new`（应只剩真改过的类），再 `jar tf | wc -l` 确认条目数（基线 **2027**）不变
- 回滚备份：`saves\HeavenMS-zhoubw_083.jar.bak-20260920`、`…bak-20260921`
- ⚠️ **09-20 全天改动曾只编译没打包**（服务端一直跑 09-19 18:40 的老 jar）。**以后改完必须打包**

## 六、排查手法（复用）

| 场景 | 手法 |
|---|---|
| 服务端卡住 / 线程死锁 | `jstack.exe <PID>`，找 `BLOCKED` 和 `- locked <同一把锁>` |
| 数 TIME_WAIT 连接数 | 用**宽松**匹配 `includes('TIME_WAIT')`；**正则带 `$` 会漏匹配**（曾把 18833 误报成 0） |
| 判断服务端是否真的启动完成 | 看控制台是否有 `Channel 1: Listening on port 7575`。**只看到 8484/7575 LISTENING 不算**（MINA 先绑端口） |
| 清 TIME_WAIT | 管理员 CMD：`netsh int ipv4 set dynamicport tcp start=10000 num=55535`（立即生效，**不清空**已有连接，只抬高天花板）。⚠️ 只重启服务端没用 |
| 验证脚本逻辑 | `jjs.exe`（Nashorn）跑 `D:\tmp\test-nashorn.js`，见 `脚本编码与测试方法.md` |
| 验证脚本编码 | `D:\tmp\encverify\EncVerify.java` |
| 盘点类有哪些 public 方法 | 用 node 正则扫 `public` 签名一次拿全貌 |
