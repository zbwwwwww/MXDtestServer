# 脚本编码与测试方法（HeavenMS 083）

> 建立于 2026-09-21。解决「客户端里 NPC/脚本中文全乱码」的根因，并沉淀一套**不依赖客户端**就能验证脚本正确性的方法。

---

## 一、中文乱码：根因与修复

### 症状
脚本（`scripts/npc/*.js`）里的中文，在客户端 NPC 对话框、物品名提示、聊天提示里全部显示成乱码汉字（如「鍔熻兘鑿滃崟」）；服务端控制台也可能看到乱码。

### 根因（实测钉死）
`AbstractScriptManager.getScriptEngine()` 用 `FileReader` 读脚本：

```java
// 旧代码
try (FileReader fr = new FileReader(scriptFile)) {
```

`FileReader` **没有编码参数**，一律用**平台默认编码**。本机 JVM 实测：

```
file.encoding       = GBK
default Charset     = GBK
sun.jnu.encoding    = GBK
```

而 `scripts/` 目录下所有含中文的脚本（25 个）**都是 UTF-8**（IDEA 默认存 UTF-8）。
⇒ 按 GBK 去解 UTF-8 字节，中文必然乱码。

⚠️ 关键点：`start-server.bat` 里的 `chcp 65001` **只改控制台代码页，不改 JVM 的文件编码**，所以完全不起作用。

### 修复

```java
// 新代码（src/scripting/AbstractScriptManager.java）
try (InputStreamReader fr = new InputStreamReader(new FileInputStream(scriptFile), StandardCharsets.UTF_8)) {
```

导入改为 `java.io.FileInputStream` + `java.io.InputStreamReader` + `java.nio.charset.StandardCharsets`（去掉 `java.io.FileReader`）。

**只改脚本读取**，不碰封包编码（封包那边是另一回事，见第三节）。

⚠️ 改了 Java 代码就**必须重编译 + 重新打包 jar + 重启服务端**才生效（见 `MEMORY.md` 的构建章节）。

### 如何验证修复真的生效

不要只看"能跑起来"。用 `D:\tmp\encverify\EncVerify.java`（可复用）：

思路 —— 在**不加**任何 `-Dfile.encoding` 的真实环境里，把同一个脚本文件分别用两种方式读，检查读出的 char 序列能否命中一个已知的中文串（用 unicode 转义写在 Java 源码里，保证源码本身是纯 ASCII）。

实测输出：

```
JVM file.encoding   = GBK
JVM default Charset = GBK

[旧] new FileReader(f)                                  -> 找到目标中文: NO
     首处中文附近的字符码点: U+9354 U+71BB U+5158 U+947F U+6EC3 U+5D1F ...
[新] new InputStreamReader(f, StandardCharsets.UTF_8)    -> 找到目标中文: YES
     首处中文附近的字符码点: U+529F U+80FD U+83DC U+5355 ...

旧读法总长度 = 19271  新读法总长度 = 18344
RESULT: PASS
```

`U+529F U+80FD U+83DC U+5355` = **「功能菜单」** ⇒ 根因确认 + 修复有效。

⚠️ 写这种验证程序时注意：**Java 源码的注释里也不能出现 `\u`** —— 编译器在词法分析前就会处理 Unicode 转义，注释里的 `\u` 一样会报「非法的 Unicode 转义」。

## 二、怎么验证脚本对不对（不用开客户端）

### 首选：用 JDK 8 自带的 Nashorn

服务端的脚本引擎就是 Nashorn。JDK 8 的 `jjs.exe` 是同一个引擎的 shell，**用它跑测试最有说服力**——能一并验证 ES 版本兼容性。

```bash
"C:\Program Files\Eclipse Adoptium\jdk-8.0.502.7-hotspot\bin\jjs.exe" -J-Dfile.encoding=UTF-8 D:\tmp\test-nashorn.js
```

测试骨架（完整版见 `D:\tmp\test-nashorn.js`）：

```js
var SCRIPT = 'D:/MXDtestServer/scripts/npc/gm_menu.js';

/* 1. 造一个假的 cm 对象，把所有被脚本调用的方法都实现出来 */
function makeEnv(opts) { /* 返回 {cm, ground, monsters, ...} */ }

/* 2. 每跑一个用例前重新 load 一次脚本 —— Nashorn 的 load 把 var status/family 放回初始值，
      等价于服务端为一个新 client 新建 script engine */
function boot(opts) {
    var env = makeEnv(opts);
    load(SCRIPT);
    cm = env.cm;          // 脚本里裸写的 cm 会从全局作用域解析
    return env;
}

/* 3. 直接按真实交互顺序驱动状态机 */
env = boot({ ground: [{id:1},{id:2},{id:3}] });
start(); action(1, 0, 10); action(1, 0, 0);   // 开菜单 → 更多功能 → 捡物
```

### 关键坑（踩过才知道）

| 坑 | 说明 |
|---|---|
| **Nashorn = ES5.1** | 脚本里不能出现箭头函数、`let`/`const`、模板字符串。正则、中文 key（加引号即可）都支持 |
| **桩必须忠于真实语义** | 比如 `map.getItems()` 的真实实现（`MapleMap.java:3093`）**每次都 `new LinkedList` 返回快照**，桩里也必须 `slice()` 返回拷贝；否则遍历中删元素会索引错位，把正确的脚本误判成有 bug |
| **用例之间要重置** | `cm.dispose()` 在真实服务端 = 结束本次对话，**下次点 NPC 会重新 `start()`**。所以每条独立流程开头都要 `start()`，否则 `status` 会停在上一个流程里 |
| **计数要取基线** | 断言 `disposed` 次数前先记 `d0 = cm.disposed`，比 `d0 + 1`，别写绝对值 |
| **`load()` 的作用域** | 在函数里 `load()` 时，脚本顶层 `var` 是否落到全局取决于引擎实现；本套件已验证可行，若遇到取不到 `status` 就改成在**顶层**调用 `load()` |

### 备选：node + `vm` 模块
`D:\tmp\test-gmmenu.js`。跑得快、断言写起来舒服，但引擎是 V8（ES2020+），**不能验证 ES5 兼容性**，只能验证逻辑。两个都保留、都跑一遍最稳。

## 三、脚本里的中文必须能被 GB2312 编码

封包发中文时是**硬编码 GB2312**（`GenericLittleEndianWriter.java:35`），和 JVM 的 `file.encoding` 无关。

所以脚本**字符串字面量**里的中文如果超出 GB2312 字符集（emoji、`⚠`、某些符号），到了客户端会变成 `?`。

检查方法（python 一行）：

```python
import pathlib
src = pathlib.Path('scripts/npc/gm_menu.js').read_text(encoding='utf-8')
bad = [c for c in sorted({c for c in src if ord(c) > 127}) if not _ok(c)]  # 逐个试 c.encode('gb2312')
```

`gm_menu.js` 实测：**代码区 258 种非 ASCII 字符全部 GB2312 可编码** ✅（含 `…`、`→`、`【】`、`｜`、`、`、`。`）。
唯一不可编码的是注释里的 `⚠️`（U+26A0 / U+FE0F）——注释不会进客户端，**无害**。

> 结论：以后在脚本里加中文，**避免 emoji 和生僻符号**，用常见简体字 + `★ → … 【】` 这类 GB2312 内的符号。

## 四、脚本缓存：改完为什么"没生效"

`AbstractScriptManager.getScriptEngine(path, client)` **按 `MapleClient` 缓存 script engine**。

⇒ 改完脚本，必须**把客户端完全关掉再重开**（切角色/回登录界面都不算），服务端不用重启。

（对比：改 Java 代码 / DB / `config.yaml` / wz ⇒ 必须**重启服务端**，客户端不用动。）

## 五、快速自检清单

改完脚本后，按顺序过一遍：

1. 文件是 **UTF-8、无 BOM**，换行 LF 或 CRLF 都行（`FileReader` 时代不敏感，现在显式 UTF-8 也不敏感）
2. `gm_menu.js` 与 `9010000.js` **字节级一致** → `cmp a b` 或比 md5
3. 字符串里的中文 **GB2312 可编码**（第三节）
4. `jjs` 测试全绿（第二节）
5. 完全关闭客户端重开，点 NPC 实测
