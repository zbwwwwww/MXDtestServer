## 一、一句话结论

| 你想改的 | 改哪儿 | 生效条件 |
|---|---|---|
| 人物**基础**四维（力量/敏捷/智力/幸运） | `characters` 表 `str`/`dex`/`int`/`luk` | **退游戏**改 → 重新登录生效 |
| 人物**攻击力** | ❌ **没有这个字段，也改不了** | 它是派生的（见第二节） |
| **某一件**装备的属性 | `inventoryequipment` 表里那件物品那一行 | **退游戏**改 → 重登生效；**不用重启服务端** |
| 某种装备的**出厂属性**（以后刷出来的） | `wz\Character.wz\<部位>\0<ID>.img.xml` | **必须重启服务端**；只影响改后新刷的 |
| 装备的**穿戴要求**（等级/职业/人气） | 同上 wz | 同上；但重启后**对已拿到的也生效**（见第三节 3.3） |

## 二、为什么 `characters` 表没有"攻击力"

### 2.1 实查结果

```
mysql> SELECT COLUMN_NAME FROM information_schema.COLUMNS
       WHERE TABLE_SCHEMA='heavenms' AND TABLE_NAME='characters'
         AND (COLUMN_NAME LIKE '%atk%' OR COLUMN_NAME LIKE '%damage%' ...);
(空)      ← 一列都没有
```

`characters` 表跟属性有关的列只有：
`level`, `exp`, `str`, `dex`, `luk`, `int`, `hp`, `mp`, `maxhp`, `maxmp`, `ap`, `sp`, `fame`, `job`

**没有任何 `watk` / `matk` / `damage` 列。**

### 2.2 攻击力是每次登录"算"出来的

```
MapleCharacter.java:204   private transient int localstr, localdex, localluk, localint_, localmagic, localwatk;
MapleCharacter.java:5370  public int getTotalWatk() { return localwatk; }
```

`localwatk` 是 **transient（不落库）**，由 `reapplyLocalStats()` / `recalcEquipStats()` 每次重算：

```java
// MapleCharacter.java:7779  遍历身上 EQUIPPED 里每一件
for (Item item : getInventory(MapleInventoryType.EQUIPPED)) {
    Equip equip = (Equip) item;
    equipstr  += equip.getStr();      // ← 装备的力量
    equipwatk += equip.getWatk();     // ← 装备的物攻
    ...
}
localstr += equipstr;
localwatk += equipwatk;               // :7801
// 之后再加 BUFF：连击 / 能量充能 / 枫叶战士 / 攻击药水 …（:7835~7911）
```

⇒ **`角色攻击力 = Σ(身上每件装备的 watk) + BUFF 加成`**。
想"加攻击力"只有两条路：**换/改装备**，或**上 BUFF**。

### 2.3 那 `characters.str` 改了有用吗？

有用。`getTotalStr() = localstr = characters.str(基础) + 装备加成 + BUFF`（`:7798`）。
改了基础四维，物攻/伤害公式里的 STR/DEX 项就变了（见 `AbstractDealDamageHandler.java:658~664`）。
但它**不等价于改攻击力** —— 物理职业的伤害还挂 `watk`。

## 三、装备属性：wz 是「模板」，数据库是「实例」★★★

这是最容易踩坑的地方。**同一件装备的数值有两个存放点，而且不总是同步。**

### 3.1 创建那一刻：wz → 内存 → DB

```
MapleItemInformationProvider.java:1034  getEquipById(equipId)
    ├─ :1038  Map<String,Integer> stats = this.getEquipStats(equipId);   ← 读 wz
    └─ :1040  逐项塞进 Equip 对象：STR→setStr, PAD→setWatk, PDD→setWdef,
                                    MAD→setMatk, MDD→setMdef, ACC→setAcc,
                                    EVA→setAvoid, Speed→setSpeed, Jump→setJump,
                                    MHP→setHp, MMP→setMp, tuc→setUpgradeSlots
                ↓
        ItemFactory.java:242  INSERT INTO inventoryequipment VALUES (…)      ← 落库
```

### 3.2 之后每次加载：**只认数据库**

```
ItemFactory.java:88  loadEquipFromResultSet(ResultSet rs)
    Equip equip = new Equip(rs.getInt("itemid"), …);
    equip.setStr((short) rs.getInt("str"));     // ← 全部来自 DB
    equip.setWatk((short) rs.getInt("watk"));
    equip.setWdef / setMdef / setAcc / setAvoid / setSpeed / setJump / setHp / setMp
    equip.setUpgradeSlots((byte) rs.getInt("upgradeslots"));
    …
```

**`loadEquipFromResultSet` 里没有任何一行去读 wz。** ⇒

> ⚠️ **已经刷出来的那件装备，属性已经固化在 `inventoryequipment` 表里。**
> **改 wz 对它完全没用** —— 只影响"改完之后新产生"的同类装备。

### 3.3 但有两类东西是**运行时实时读 wz** 的

`getEquipStats(itemId)`（`:517`）返回的那张表里，除了 `inc*` 属性数值，还有：

| 字段 | 谁在读 | 改 wz 后 |
|---|---|---|
| `reqLevel` / `reqJob` / `reqSTR`… / `reqPOP` | `canWearEquip()`（`:1640~1720`）、`getEquipLevelReq()`（`:551`） | **对所有已存在的同类装备立即生效**（重启后） |
| `cash`（是否现金物品） | `getEquipStats(...).get("cash")` | 同上 |
| `tuc`（可升级次数） | 创建时抄进 DB 的 `upgradeslots`，之后以 DB 为准 | 只对新物品 |
| `inc*`（力量/物攻/防御…） | 创建时抄进 DB | **只对新物品** |

⇒ 想"把维泽特帽的等级要求从 0 改成 120"，改 wz 就够了，老帽子也跟着变。
想"把维泽特帽的力量从 999 改成 5000"，改 wz **只对以后刷的有效**。

### 3.4 ⚠️ 有内存缓存，改 wz 必须重启服务端

```
MapleItemInformationProvider.java:517  getEquipStats(itemId) {
    if (equipStatsCache.containsKey(itemId)) return equipStatsCache.get(itemId);   // ← 内存缓存
    … reads wz …
    equipStatsCache.put(itemId, ret);
}
```

装备/物品相关的缓存（`equipStatsCache` / `equipLevelReqCache` / `equipmentSlotCache` /
`itemNameCache` …）**都是一次性加载、没有热重载入口** ⇒ **改 wz 必须重启服务端**。

### 3.5 wz 读的是 XML 还是二进制？—— 是 XML，可以直接改

```
MapleDataProviderFactory.java:33  if (in.getName().endsWith("wz") && !in.isDirectory())
                                      return new WZFile(in, false);     // 二进制
                                  return new XMLWZFile(in);             // ← 目录 → 读 .img.xml

XMLWZFile.java:57   File dataFile = new File(root, path + ".xml");      // 补 .xml 后缀
```

`D:\MXDtestServer\wz\Character.wz` 是个**目录** ⇒ 走 `XMLWZFile` ⇒ 读 `01002140.img.xml`。
**所以直接编辑那些 `.img.xml` 是有效的**（二进制 `WZFile` 才是不可改的）。

## 六、风险清单（都不大，但都是真会中的）

| # | 风险 | 说明 / 规避 |
|---|---|---|
| 1 | **32767 上限（short）** | `Equip.setStr/setWatk/…` 全是 **`short`**，封包也是 `writeShort`。写 `>32767` 会**溢出成负数**。单值最大 **32767** |
| 2 | **在线改必被覆盖** | 退出角色时 `saveCharToDB`（`MapleCharacter.java:8447~8471`）会把**内存里的值写回** `characters`；物品同理。改 DB **必须先退到登录界面 / 关客户端** |
| 3 | 建议**改前备份那一行** | `CREATE TABLE inventoryequipment_bak0909 AS SELECT * FROM inventoryequipment;`（一行 SELECT 也行） |
| 4 | **客户端 tooltip 可能不同步** | 见第七节 |
| 5 | 数值过大会影响伤害计算 | `calculateMaxBaseDamage(watk)` 等是 int 运算，32767 级不会崩，但数字会很夸张 |
| 6 | 改 wz 忘了重启 | 症状：改了没反应。判据见 `开发避坑清单.md`（控制台出现 `Channel 1: Listening on port 7575`） |

## 七、客户端会跟着显示新数值吗？（未离线证实，建议实测一次）

- 客户端**属性数值的来源是服务端封包**：`MaplePacketCreator.addItemInfo()`（`:437~453`）
  会把服务端 `Equip` 对象的 `str/dex/int/luk/hp/mp/watk/matk/wdef/mdef/acc/avoid/hands/speed/jump`
  **整套发给客户端**（绝对值，不是增量）。
  ⇒ 理论上**改服务端就会显示新数值**（滚卷轴能显示加成，走的也是这套）。
- **但装备的图标/外观 100% 来自客户端自己的 wz**（服务端 wz 里没有图形）。所以：
  - 只改数值 ⇒ 大概率正常
  - 换成"客户端 wz 里根本没收录的装备" ⇒ 客户端画不出来、tooltip 空
- ⚠️ 客户端 `Character.wz`（1.15GB）是 `PKG1` + 防解包加密，**离线不可读也不可改**。
  所以万一实测发现 tooltip 不跟服务端走，**普通手段修不了客户端那份**。

**验证办法（1 分钟）**：帽子 `incSTR` 已由 999 改成 **32767** → 重启服务端 → 刷一顶 → 看 tooltip 显示 `32767` 还是 `999`。
- 显示 `32767` ⇒ 封包为准，改服务端就够 ✅
- 仍显示 `999` ⇒ 客户端 wz 为准，那条路就走不通（只能接受数值与显示不一致）⚠️

（注：手上那顶 `inventoryitemid=6646` 现在库里也是 32767，**戴上去直接就能看 tooltip**，不必等新刷。）
