| 问题 | 答案 |
|---|---|
| 单件装备的攻击能改到多少？ | **32767** —— 唯一硬墙（`short`，wz/DB/封包三条路都是 2 字节、**全无 clamp**） |

**★ 最关键的一条**：`wz 加载` / `DB 加载` / `发客户端` **三处全是 `(short)`，没有一处 clamp**

**对照（说明这不是普遍规律，物攻是特例）**：
`localmagic` 在 `MapleCharacter.java:7821` 被 `Math.min(localmagic, 2000)` **卡死在 2000**，
`calculateMaxBaseMagicDamage`（`:834~852`）还额外给了 `totalint > 2000` 的分段公式
⇒ **魔攻有天花板，物攻没有**。

## 2. 总攻 `localwatk` 到底由什么组成

`MapleCharacter.java:7816~7911`（`reapplyLocalStats`），全部是 `+=`：

```
localwatk  = 0
           += equipwatk            // Σ 身上每件的 watk（:7801）
           += Aran 连击 getX()      // :7837
           += 能量充能 getWatk()    // :7843（energybar==15000）
           += 弓手专精 getX()       // :7863（3220004 / 3120005）
           += WATK buff             // :7870（愤怒之火等）
           += 祝福(blessing)        // :7890（技能等级，个位数）
           += 子弹的 incPAD         // :7911（弓/弩/拳套/枪 且背包里有对应弹药）
```

- **件数没有硬编码上限**：`recalcEquipStats` 是 `for (Item item : getInventory(EQUIPPED))` **全遍历**；
  加载走 `ItemFactory.java:120 loadEquippedItems`，**纯按 DB 行数来、没有任何槽位数量校验**（`:138~147`）。
- ⇒ 理论值 = `件数 × 32767 + buff/子弹`，绝对硬顶 **2,147,483,647**。
- 实际受客户端装备槽位数约束（有效槽 ~20 个）⇒ 现实可达量级 **~65 万**。

## 3. 派生伤害公式

`MapleCharacter.java:794~811`

```
mainstat / secondarystat 按武器类型选：
  弓 / 弩 / 枪(GUN)  → 主 = localdex，副 = localstr
  拳套(CLAW) / 盗贼短刀 → 主 = localluk，副 = localdex + localstr
  其余（含 KNUCKLE / 剑 / 矛 / 杖）→ 主 = localstr，副 = localdex

calcDmgMax = (int) Math.ceil( ((武器倍率 × 主 + 副) / 100.0) × 总攻 )
```

**武器倍率**取自 `MapleWeaponType.getMaxDamageMultiplier()`（枚举硬编码，不是 wz 字段）：

| 倍率 | 武器类型 |
|---|---|
| **5.0** | `POLE_ARM_SWING`（矛/枪 挥）、`SPEAR_STAB` |
| 4.8 | `GENERAL2H_SWING`、`KNUCKLE`（拳套） |
| 4.6 | `SWORD2H` |
| 4.4 | `GENERAL1H_SWING` |
| 4.0 | `SWORD1H`、`DAGGER_OTHER` |
| 3.6 | `BOW`/`CLAW`/`CROSSBOW`/`DAGGER_THIEVES`/`GUN`/`STAFF`/`WAND` |
| 3.4 | `GENERAL2H_STAB`、`BOW` |
| 3.2 / 3.0 | `GENERAL1H_STAB`、`POLE_ARM_STAB`、`SPEAR_SWING` |

⚠️ **武器类型由 `itemId` 的品类段决定**，不是 wz 里写的：
`MapleItemInformationProvider.java:587` → `cat = (itemId / 10000) % 100`，取 `type[cat - 30]`（30~49 有效）。
⇒ **换武器 = 直接换倍率和主属性**，比堆攻更省事。

**饱和而非回绕**：结果是 `double` 先算、再 `(int)` 强转。Java 的 `double → int` 是**饱和转换**
（JLS 5.1.3），超过 `Integer.MAX_VALUE` 就**钉死在 2,147,483,647** —— 这是全链路唯一一处 Java 兜底。

## 5. 客户端上限 —— 「99999」是错的，已实测推翻

> **2026-09-22 用户上机实测：打出十几万 / 二十几万伤害。北冥客户端没有 99999 上限。**
> 上一版那条「083 单排上限约 99999」是按官服史料推的，**作废**。

真正的机制**不是"某个数字封顶"，而是正负号编码**：

- 客户端上报的每段伤害是 **4 字节 `int`**（`:863` `lea.readInt()`）⇒ 单段协议上限 **2,147,483,647**。
- 超过常规范围的伤害，写成**负数**：`encoded = damage + Integer.MIN_VALUE`。
  服务端解码见 `:287` —— `if(eachd < 0) eachd += Integer.MAX_VALUE;`（还原后比原值少 1，无影响）。
- 服务端**自己也编这份码**，但**只对 `canCrit` 职业**（`:888~890`：弓手/飞侠/夜行者/风灵/战神3-4/拳霸）。
  **战士 `canCrit = false`** ⇒ 你打出的负值伤害**只可能来自客户端自身**，服务端全程不参与、不校验、不设卡。
- ⇒ **能打多少完全由客户端决定，上限就是 `int` 的 2,147,483,647。**

另外一条仍然成立：
**面板「攻击力」是客户端自己算的**。`MapleStat` 枚举里**没有 `WATK`**（`MapleStat.java:26~45`），
`updatePlayerStats`（`MaplePacketCreator.java:1005`）只发 `SKIN/FACE/HAIR/LEVEL/JOB/STR/DEX/INT/LUK/HP/MP/MAXHP/MAXMP/AP/SP/EXP/FAME/MESO`
⇒ **服务端从不发聚合攻**，客户端把身上每件的 watk（收到的是 **signed short**）+ buff 自己加起来显示。
（速度/跳跃同理，`MapleCharacter` 连字段都没有 —— 见另一份文档。）

### 5.1 ★★ 实战真会炸的那堵墙：总伤害 `int` 溢出

```
AbstractDealDamageHandler.java:261   int totDamageToOneMonster = 0;
                          :286~288   for (Integer eachd : onedList) {
                                         if(eachd < 0) eachd += Integer.MAX_VALUE;  // 解码
                                         totDamageToOneMonster += eachd;            // ← int 累加，零保护
                                     }
                          :522       map.damageMonster(player, monster, totDamageToOneMonster);
```
`MapleMonster.applyAndGetHpDamage(:351)`：
```java
if (delta >= 0) {                       // 正常扣血：trueDamage = min(curHp, delta)，不会过度扣
    ...
} else {
    int trueHeal = -delta;              // ← delta 为负时走这里：怪物回血
    ...
}
```
⇒ **一次攻击所有段相加 ≥ 2^31 就溢出为负 → 怪物不掉血，反而回血**（永远打不死）。
⇒ 实用约束：**单段伤害 × 段数 < 2,147,483,647**

| 技能段数 | 单段安全上限（约） |
|---|---|
| 8 段 | **2.68 亿** |
| 6 段 | 3.57 亿 |
| 3 段 | 7.15 亿 |
| 1 段 | 21.4 亿 |

⚠️ 这是**唯一会在实战里炸**的点，比"客户端显示"重要得多。

## 六、单段伤害实测钉死在 1,333,333,337 —— 封顶在客户端（2026-09-22 晚源码实查）

用户实测：拉满装备后**单段最高 1,333,333,337，再上不去**。实读 `AbstractDealDamageHandler.java` 结论：

| 事实 | 源码位置 | 含义 |
|---|---|---|
| 每段伤害是**客户端算好发上来**的 | `:863` `int damage = lea.readInt()` | 服务端**不重算、也不钳制**单段伤害 |
| `calcDmgMax` 只当 crit 翻转阈值用 | `:653~664` 算出 → `:888` `canCrit && damage > hitDmgMax` 时 `damage = -Integer.MAX_VALUE + damage - 1` | 这是**大伤害负值编码**（给其它客户端显示用），不是上限钳制 |
| 解码与编码差 1（off-by-one） | `:287` `eachd += Integer.MAX_VALUE` vs `:890` 编码 `-MAX + d - 1` | 解回 `d-1`，每段少 1 点，无害 |
| 累加溢出 | `:288` `totDamageToOneMonster += eachd`（int，零保护） | 即 §5.1 的真墙 |

⇒ **1,333,333,337 这个数不在服务端源码里**（全 src grep 无此常数）。伤害数值由北冥版 083 客户端计算并上报，**封顶在客户端**：
- 机制推断：客户端算 maxDamage ≈ 34.87 亿（服务端同公式饱和前值）→ 超出 int32 → 回绕/解包后呈现为 ≈ 13.3 亿的正数封顶（≈ `Integer.MAX_VALUE` × 0.62）。
- **属性再强也不会变**：服务端 `calcDmgMax` 早已饱和 21.47 亿，远超客户端能表达的量程。
- 客户端 `Character.wz` 为 PKG1 加密（见《装备与人物属性-存在哪-怎么改.md》§七），常数读不到、改不了。
- 服务端侧唯一可改的相关墙 = §5.1 的 `totDamageToOneMonster` int 溢出（int→long，重编译生效）；客户端显示上限改不了。

**实用结论**：单段伤害天花板 ≈ 13.33 亿（客户端封顶）；任何 **≥2 段**技能必然触发 §5.1 溢出（13.33 亿 × 2 = 26.6 亿 > 21.47 亿）→ 怪物回血。想秒杀请用**单段技能**。

## 6. 提升路径（按杠杆排序）

| 做法 | 效果 | 代价 |
|---|---|---|
| **换武器**（改 `itemId` 品类段） | 直接换倍率（最高 5.0）+ 主属性 | 要重新刷一把 |
| **武器 `incPAD` 200 → 32767** | 单件一步拉满，最直接 | **wz + DB 双改**（重启 + 退游戏） |
| 给帽子 wz 加 `<int name="incPAD" value="N"/>` | 帽子也能加攻 | 同上 |
| 给西装/裤/鞋/披风加 `incPAD` | 多件叠加 | 同上 |
| WATK buff（愤怒之火等） | 每条也 ≤ 32767 | 改技能 wz |
| 叠 `incSTR`（喂主属性） | 公式里主属性也乘倍率，杠杆同样大 | 见单件属性上限表 |

**帽子可以加攻**：`getEquipStats`（`MapleItemInformationProvider.java:530~534`）会把 `info` 下所有
`inc*` 节点**自动去前缀**收进 map（`incPAD` → `PAD`），`getEquipById:1049` 认 `"PAD"` → `setWatk`。
所以手动加一个 `incPAD` 节点即可生效。

### 6.1 wz 里 `inc*` 字段对照表

链路：`getEquipStats:530~534` 去掉 `inc` 前缀 → `getEquipById:1041~1070` 按 key 认领并 `set*`

| wz 节点 | 去前缀后 | 落到 `Equip` 字段 | 含义 |
|---|---|---|---|
| `incSTR/DEX/INT/LUK` | `STR/DEX/INT/LUK` | `str/dex/int/luk` | 四维（通过公式间接放大伤害） |
| **`incPAD`** | `PAD` | **`watk`** | **物攻 —— 就是"装备加的攻击力"** |
| `incMAD` | `MAD` | `matk` | 魔攻 |
| `incPDD` / `incMDD` | `PDD` / `MDD` | `wdef` / `mdef` | 物防 / 魔防 |
| `incACC` / `incEVA` | `ACC` / `EVA` | `acc` / `avoid` | 命中 / 回避 |
| `incSpeed` / `incJump` | `Speed` / `Jump` | `speed` / `jump` | 速度 / 跳跃 |
| `incMHP` / `incMMP` | `MHP` / `MMP` | `hp` / `mp` | 加 HP / 加 MP |
| `tuc`（**无 `inc` 前缀**） | — | `upgradeSlots` | 可升级次数 |

⚠️ **`incPADr` / `incMADr`（百分比攻击）本版本不认** —— 全源码只有 `"PAD"` / `"MAD"` 两个 key
（`grep` 过 `PADr`/`MADr`：**零命中**）⇒ 写成 `incPADr` 会被**静默忽略**，不报错、不生效。
⚠️ 这些值仍受 **32767** 约束；wz 加载那条路是裸 `(short)`、无 clamp（见 §1）。

**和"面板攻击力"的关系**：面板攻 = `Σ(每件 watk) + buff`，所以 `incPAD` 是它的**主要来源，但不是唯一来源**
—— `incPAD` 只决定"装备这一份"；武器倍率、四维、buff 各自另算。

## 7. 怎么验证（服务端不自证）

面板是客户端算的，服务端不参与 ⇒ **只能上机看**：

1. 改 → 武器走 wz **重启服务端**、DB 走**退游戏重登**
2. 开客户端 → 看面板「攻击力」数字
3. 打**同一只怪**，记录**单排最高伤害**
4. 逐级加码（建议阶梯 `32767 → 65534 → 131068 → …`），看**从哪一档开始伤害不再涨** ⇒ 那就是客户端真正的上限
5. **同时盯「怪物回血 / 打不死」**：一旦出现，就是撞了 §5.1 的 `int` 总伤害溢出 —— 把单段降下来即恢复
6. 若要摸客户端显示上限，一次只加**单件**、单段技能测（段数多的会先被 §5.1 的溢出挡住，测不出显示墙）

## 8. 不要做的事

| ❌ | 原因 |
|---|---|
| 单件写 `32768` 及以上 | 静默变负，面板攻击力**反而掉** |
| 直接改 `characters.str` 超 `32767` | 基础四维面板封包是 2 字节，显示会乱（`localstr` 虽然能吃 int，但没必要） |
| 期待「攻击力 ↑ = 伤害线性 ↑」 | 客户端的墙在前面，过了就白改 |
| 段数多的技能把单段堆到上亿 | **总伤害 `int` 溢出 → 怪物回血**（`AbstractDealDamageHandler.java:288` 无保护，§5.1） |

| 在线改 DB 装备属性 | 退出时 `saveCharToDB` 会把内存值写回覆盖 —— **必须先退游戏** |

## 9. ✅ 多段溢出修复记录（2026-09-22 22:10）

§5.1 的 `totDamageToOneMonster` 溢出**已修复**（用户实测 20 件拉满后多段必现怪物回血）：

**改法（最小钳制，非改签名）**：`AbstractDealDamageHandler.java`
| 位置 | 改动 |
|---|---|
| `:261` | `int totDamageToOneMonster` → `long totDamageAccToOneMonster`（long 累加器） |
| `:291` | 循环后 `int totDamageToOneMonster = (int) Math.min(totDamageAccToOneMonster, (long) Integer.MAX_VALUE)` |
