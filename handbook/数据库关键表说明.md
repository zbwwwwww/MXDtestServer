## 一、先纠正一个前提（最重要）

你想找的四张表，**只有一张真的在数据库里**：

| 你以为的表 | 实际在哪 | 说明 |
|---|---|---|
| 怪物掉落概率表 | ✅ **在数据库** `drop_data` | 22309 条 |
| 怪物经验倍率表 | ❌ **不在数据库** | 倍率在 `config.yaml`；怪物基础经验在 `wz/Mob.wz/<7位ID>.img.xml` 的 `info/exp` |
| 物品表 | ❌ **不在数据库** | 属性在 `wz/Item.wz/`，中文名在 `wz/String.wz/*.img.xml` |
| 怪物表 | ❌ **不在数据库** | 属性（HP/EXP/等级/攻防）在 `wz/Mob.wz/<7位ID>.img.xml`，中文名在 `wz/String.wz/Mob.img.xml` |

**规律**：数据库只放「关系型 / 会变的数据」——谁掉什么、哪个 NPC 卖什么、玩家存档。
**静态配置**（怪物多强、物品什么样、叫什么名字）全在 `wz/` 目录的 XML 里。

### 以「蜗牛」为例，它的数据被拆成三处

| 数据 | 位置 | 内容 |
|---|---|---|
| 名字 | `wz/String.wz/Mob.img.xml` → `100100` | 蜗牛 |
| 属性 | `wz/Mob.wz/0100100.img.xml` → `info` 节点 | `exp=3`、`maxHP=8`、`level=1`、`PADamage=12` |
| 掉落 | 数据库 `drop_data` → `dropperid=100100` | 17 条掉落记录 |

> `Mob.wz` 的文件名是 **7 位补零**：怪物 ID `100100` → 文件 `0100100.img.xml`

## 三、三种 `chance`，语义完全不同 ⚠️ 最容易踩的坑

| 表 | 源码里的判定公式 | 方向 | 例子 |
|---|---|---|---|
| `drop_data` | `random(999999) < chance × 掉落倍率 × 卡片倍率` | **越大越容易掉** | `600000` = 60%；`1000000` = 100% |
| `drop_data_global` | `random(999999) < chance`（**不乘倍率**） | **越大越容易掉** | `35000` = 3.5% |
| `reactordrops` | `random() < 掉落倍率 ÷ chance` | ⚠️ **越小越容易掉！** | `1` = 100%；`2` = 50% |

源码位置：
- `server/maps/MapleMap.java:656-658`（drop_data）
- `server/maps/MapleMap.java:700`（drop_data_global）
- `scripting/reactor/ReactorActionManager.java:242`（reactordrops）
- `MapleMap.java:765` 有行注释 `int chRate = 1000000;   // guaranteed item drop` —— 这就是"百万分之"的铁证

### `drop_data` 换算口诀

> **百分比 = chance ÷ 10000**

## 四、你的核心问题：改完要不要重启？

### 结论

> **几乎所有 DB 数据改动，都必须重启服务端。客户端一律不用重启。**

原因：服务端把数据读进内存后就**永久缓存**，而且**没有热重载入口**（我把相关方法全搜过了）。

| 你改什么 | 重启服务端 | 重开客户端 | 源码依据 |
|---|---|---|---|
| `drop_data` 怪物掉落 | ✅ **必须** | ❌ 不用 | `MapleMonsterInformationProvider.java:219` 首次查该怪时读库并缓存 |
| `drop_data_global` | ✅ **必须** | ❌ 不用 | 同文件 `:72` 构造函数里**启动时一次性加载** |
| `reactordrops` | ✅ 必须 | ❌ 不用 | `ReactorScriptManager.java:101` 同样缓存 |
| `shops` / `shopitems` | ✅ 必须 | ❌ 不用 | `MapleShopFactory.java:59` 首次开店时读库并缓存 |
| `config.yaml` 倍率 | ✅ 必须 | ❌ 不用 | 启动时读 YAML |
| `wz/*` 怪物/物品属性 | ✅ 必须 | ❌ 不用 | 启动时加载 wz |
| `characters` 角色数据 | ⚠️ **先退游戏再改** | ✅ 要重进角色 | 内存才是权威，且会定时覆盖写回 |
| `wz_names`（我给你的映射表） | ❌ **不用** | ❌ 不用 | 服务端根本不读它，纯查询用 |

### ⚠️ 两个最容易误判的陷阱

**陷阱 1：`drop_data` 是"懒加载"，所以看起来像"有时不用重启"**

它的加载逻辑是「第一次有人查这个怪 → 读库 → 存进 `drops` 这个 Map → 以后永远用内存里的」。
所以：改完不重启，**那个怪只要被击杀过一次，就永远用旧数据**。
而且 `clearDrops()` 这个方法虽然存在，但**全项目没有任何地方调用它** —— 也就是说**没有清缓存的入口**，只能重启。

**陷阱 2：`characters` 表绝对不要在游戏运行时改**

服务端把角色数据全放在内存里当权威。你在游戏里用 MySQL Workbench 改 `characters` 的字段，会被：
1. 存档时用内存值**覆盖写回**（`USE_AUTOSAVE` 每小时一次）
2. 甚至更早，在你做任何会触发存档的操作时

**正确做法**：完全退出游戏 → 改库 → 再进游戏。
（这个坑我们之前就踩过：改 `gm` 字段必须先退游戏）

### 唯一不用重启的改动

新增/查询性质的表 —— 比如本次生成的 `wz_names` 映射表，服务端不读它，你随时改随时生效。

## 五、经验 / 掉落倍率在哪调

在 **`config.yaml` 第 4~17 行**，按 **world（服务器）** 配置：

```yaml
worlds:
    #Properties for Scania 0
  - flag: 3
    server_message: 欢迎来到，江城冒险岛beta4.0！
    channels: 1
    exp_rate: 5            # 经验倍率  ← 你现在是 5
    meso_rate: 1           # 金币倍率
    drop_rate: 1           # 普通怪掉落倍率  ← 现在是 1（原版）
    boss_drop_rate: 1      # BOSS 掉落倍率（覆盖 drop_rate）
    quest_rate: 1          # 任务经验/金币倍率
    fishing_rate: 1
    travel_rate: 1
```

- 你现在只用 **world 0（Scania）**，所以改第一段就生效
- 下面那些 world（Bera/Broa/...）没配倍率，用的是默认值

### 最终经验公式

```
实际经验 = 怪物基础 exp（wz 里）× exp_rate × 其他加成（组队/道具）
```

蜗牛：`3 × 5 = 15` 点经验/只。

源码：`server/life/MapleMonster.java:719`（`partyExp *= attacker.getExpRate()`）

> ⚠️ 改完 `config.yaml` **必须重启服务端**才生效。

## 六、交付的三个文件

| 文件 | 用途 |
|---|---|
| `handbook/wz_id_lookup.html` | **可搜索速查页**，双击用浏览器打开，输 ID 或中文名都能查 |
| `sql/wz_name_tables.sql` | 导入后建 `wz_names` 表，可**直接用 SQL JOIN** 把裸 ID 翻译成中文名 |
| `handbook/数据库关键表说明.md` | 本文件 |

### 导入 SQL 映射表（可选，推荐）

```cmd
cd /d D:\MXDtestServer\sql
mysql -uzhoubw -p040211 --default-character-set=utf8 heavenms < wz_name_tables.sql
```

导入后就能这么查了：

```sql
-- 看蜗牛掉什么（带中文名和百分比）
SELECT m.name AS 怪物,
       IF(d.itemid=0,'金币',COALESCE(i.name,'?')) AS 掉落物,
       d.chance, ROUND(d.chance/10000, 4) AS 百分比,
       d.minimum_quantity AS 最少, d.maximum_quantity AS 最多
FROM drop_data d
LEFT JOIN wz_names m ON m.kind='mob' AND m.id=d.dropperid
LEFT JOIN v_item_name i ON i.id=d.itemid
WHERE d.dropperid=100100
ORDER BY d.chance DESC;
```

`wz_name_tables.sql` 末尾还附了 6 条现成查询（掉率排行、物品反查来源怪、全局掉落翻译等），直接复制到 Workbench 就能用。
