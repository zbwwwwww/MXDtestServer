## 一、原版刷怪机制（HeavenMS）

### 刷怪点从哪来
`Map.wz/Map/MapX/<9位地图ID>.img` 的 **`life` 节点**，其中 `type=m` 的就是刷怪点（SpawnPoint）。
每一条 life 记录 = **一个刷怪点**。

另外 `plife` 表（`MapleMapFactory:85 loadLifeFromDb`，**每次加载地图都无条件读**）也能追加刷怪点 ——
该表目前 0 行，等于一个官方留的"零代码加怪点"后门。

### 三条硬规则（`SpawnPoint.java`）
| 规则 | 代码 | 含义 |
|---|---|---|
| **一个点同时只容 1 只怪** | `shouldSpawn()`：`spawnedMonsters.get() > 0` → false | 这是密度的真正天花板 |
| 怪死后等 `mobTime` **秒** | `monsterKilled()`：`nextPossibleSpawn = now + mobTime * 1000` | `mobTime` 单位是**秒**（不是毫秒） |
| `mobTime == 0` → 只等死亡动画 | `nextPossibleSpawn += aniTime` | 这是最快的一档，约 1 秒 |
| `mobTime < 0` → 一次性怪 | `shouldSpawn()` 直接 false | 剧情/BOSS 出场怪，刷一次就不再出现 |

### 补怪任务怎么跑
- `Server.java:877`：`tMan.register(new RespawnTask(), RESPAWN_INTERVAL, RESPAWN_INTERVAL)` —— 每 N 毫秒扫一遍**所有**地图
- 每张图补多少只：`MapleMap.getNumShouldSpawn()`（`MapleMap.java:3689`）
  - `USE_ENABLE_FULL_RESPAWN: true` → `刷怪点数 - 当前存活数` ⇒ **填满**
  - `false` → `ceil((0.70 + 0.05 × min(6, 玩家人数)) × 刷怪点数) - 存活数` ⇒ 单人只有 **75%**
- 地图容量上限：`fixedMobCapacity`（wz info，默认 **500**），`MapleMap.java:1991` 判超过就不再刷

### ★ 结论
> **补刷速度有三个旋钮（填满开关 / 扫描间隔 / mobTime），密度上限只有一个：刷怪点数量。**
> 前三项调到极致之后，想让怪更密，**只能增加刷怪点**。

## 三、倍率配置：`MOB_SPAWN_MULTIPLIER`

### 配置项（`config.yaml` → `server:` 段）
```yaml
    USE_ENABLE_FULL_RESPAWN: true
    RESPAWN_INTERVAL: 1000
    MOB_SPAWN_MULTIPLIER: 2    # 1=原版，2=翻倍，3=三倍
```

### 实现位置
`src/server/maps/MapleMapFactory.java` → `loadLifeRaw()`

```
copy == 0  →  wz 里的原始刷怪点（行为与改动前完全一致）
copy >= 1  →  按倍率复制出的额外刷怪点
```

复制体三条处理：
1. **X 轴交替错开**：`mobSpawnOffset(copy)` → `+45, -45, +90, -90, +135, ...`（避免全叠在同一格）
2. **重新贴地**：用 `map.getFootholds().findBelow(new Point(nx, y))` 找该 x 下方的平台，
   取它的 id 设为新的 `fh`；**找不到就直接跳过这一份** ⇒ 宁可少刷，绝不产生悬空怪
   （y 不用自己算，`addMonsterSpawn()` 内部 `calcPointBelow()` 会重新算）
3. **stats 复用原件**：`new MapleMonster(id, monster.getStats())`，避免再查一次 wz

### 排除规则（`getExtraSpawnCopies()`）
| 条件 | 原因 |
|---|---|
| `mobTime < 0` | 剧情/一次性怪，复制会重复触发 |
| `team >= 0` | 团队副本怪（怪物嘉年华等按队伍分配，复制破坏机制） |
| `monster.isBoss()` | **BOSS 绝不复制**，否则一张图刷出好几只 BOSS |

`isBoss()` 安全性已核实：`MapleLifeFactory.getMonster()` 要么返回带 stats 的实例、要么返回 `null`，
非 null 即 stats 非 null（`MapleMonsterStats.isBoss()` 只是返回 boolean 字段），不会 NPE。

## 六、⚠️ 踩坑记录（写探针时踩到的）

**绝不能在探针里调 `MapleMapFactory.loadMapFromWz()`**：
`SpawnPoint` 构造器里有 `Server.getInstance().getCurrentTime()`，而
`Server.getInstance()` 是 `if (instance == null) instance = new Server();`
—— 会**把整个服务端拉起来**，和正在跑的服务端抢 8484/7575 端口。

所以密度验证只能用**纯数据复刻**（`MapleFootholdTree` + 照抄 foothold 解析），不碰 `MapleMap`/`Server`。
参见 `D:\tmp\fixE-bench\MobDensitySimProbe.java`。
